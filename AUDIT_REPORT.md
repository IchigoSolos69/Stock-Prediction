# Project audit — 7 October 2026

> Historical pre-fix audit. Implementation updates are tracked in [FIX_STATUS.md](FIX_STATUS.md). Source line references below refer to the audited pre-fix snapshot.

The project is not currently runnable as written, and its forecast and backtest outputs are not yet reliable enough to assess model quality. The highest priorities are exposed broker credentials, import/training failures, training/inference feature mismatch, and future information entering model inputs.

This audit covered all 13 project Python files, requirements.txt, the three saved model artifacts, the CSV, and the existing application log. Application source was not changed. No broker authentication, trading, full model training, or live market-data validation was performed. Credential values are deliberately omitted from this report.

Priority labels: **Critical** means address immediately; **High** means a startup, security, or output-validity problem; **Medium** means an incorrect edge case, incomplete implementation, or reliability problem. Findings involving dormant training paths are identified explicitly.

1. **Critical — Broker secrets exist in source and logs.** [angel_bridge.py:9](C:/Users/Adi/Documents/GitHub/stock_pred/angel_bridge.py:9) contains an API key, client identifier, password/PIN value, and TOTP seed. [app.log:1](C:/Users/Adi/Documents/GitHub/stock_pred/logs/2025-12-26/app.log:1) contains authentication request bodies, including a password and OTPs, plus account and device/network identifiers. The log also records a rejected authentication attempt. Anyone receiving these files receives sensitive authentication material. Rotate/revoke the exposed credentials and TOTP seed through the provider, move secrets to environment or secret-store configuration, and redact authentication payloads. Remove secrets from any previously shared copies or version history if applicable. Whether these credentials remain active was not tested.

2. **High — The broker bridge prevents imports and does not implement the advertised interface.** [angel_bridge.py:62](C:/Users/Adi/Documents/GitHub/stock_pred/angel_bridge.py:62) references `SMART_API_AVAILABLE` at module scope, but that variable is assigned only inside a constructor. With SDK imports stubbed, importing the module raises `NameError`. The outer constructor defines a second nested `AngelBridge` class instead of initializing itself; an outer instance has no session, connection, history, or LTP methods. The inner methods also contain placeholder authentication/data logic. [data_loader.py:4](C:/Users/Adi/Documents/GitHub/stock_pred/data_loader.py:4) and [live_price.py:4](C:/Users/Adi/Documents/GitHub/stock_pred/live_price.py:4) import this bridge unconditionally, before the app's optional-import guard can help. Implement one bridge class and a module-level availability flag, with an explicit disconnected state and working fallback.

3. **High — Daily training is missing; other training entry points fail.** [app.py:16](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:16) imports `train_model`, which is not defined anywhere in model_trainer.py. Enhanced/stacked training calls unimported `add_advanced_features` at [model_trainer.py:27](C:/Users/Adi/Documents/GitHub/stock_pred/model_trainer.py:27) and line 153. LightGBM and several regressors are also undefined in those paths. Intraday training calls unimported `fetch_intraday_data` at [model_trainer.py:278](C:/Users/Adi/Documents/GitHub/stock_pred/model_trainer.py:278). Dependency/feed-isolated execution reproduced all three trainer failures. Simply aliasing enhanced training to `train_model` will not solve integration: it saves a different filename and `model`/`features` keys, while the app requires `_model.pkl` and `xgb_model`/`xgb_features`. Define and test a single training-to-inference contract.

4. **High — Installation is incomplete and unreproducible.** [requirements.txt:1](C:/Users/Adi/Documents/GitHub/stock_pred/requirements.txt:1) has no version constraints and omits dependencies imported by the code: SmartApi's distribution, pyotp, arch, and lightgbm. Those modules are also absent from the included environment inventory. arch is imported unconditionally by volatility.py, and the optimizer imports lightgbm even before selecting an estimator. The local `.venv` cannot launch because its base Python executable is inaccessible. Declare the supported Python version, complete and lock dependencies, and rebuild environments from configuration rather than distributing the environment directory. Separate optional broker/experimental ML dependencies from the minimal app runtime.

5. **High — The saved daily model receives a substantially different feature schema.** [features.py:91](C:/Users/Adi/Documents/GitHub/stock_pred/features.py:91) calls nonexistent `fetch_global_cues`; the existing function is `fetch_enhanced_macros`. The exception is caught, so macro features disappear. Static inspection of HINDCOPPER_model.pkl found 54 required features, including 18 macro/macro-lag columns plus `Adj Close`. The normal Yahoo `auto_adjust=True` history path does not supply `Adj Close`. [app.py:211](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:211) and line 508 silently replace all missing features with zero. Thus 19 required columns are absent on the normal Yahoo path, yet a normal-looking forecast/backtest can be shown once startup is repaired. Reject incompatible artifacts and unavailable mandatory features, restore the intended pipeline, and retrain with a versioned schema. FII/DII training features are additionally constant zero because fii_history.csv is absent; the live whale widget does not supply historical model features.

6. **High — Intraday training includes the answer in its inputs.** [features.py:169](C:/Users/Adi/Documents/GitHub/stock_pred/features.py:169) creates `Target_Return` from the next bar. [model_trainer.py:286](C:/Users/Adi/Documents/GitHub/stock_pred/model_trainer.py:286) does not exclude it from input features. Synthetic evaluation confirmed that this selected input equals the 5m target exactly; longer horizons also receive future first-bar information. The final live row cannot contain that value. Build predictor columns independently from labels and test that appending future bars cannot change prior predictors. This defect concerns the current training code; the existing intraday artifact has a different five-feature schema and was not shown to contain this leaked target.

7. **High — Backtest metrics are incorrect and evaluate a different strategy.** [app.py:519](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:519) shifts returns after removing the final unlabeled feature row, losing the latest otherwise-known return. Lines 529–530 report cumulative log returns multiplied by 100 as percentage profit; two +10% days show 19.06% instead of 21%. Line 531 can count an unknown final outcome as a losing trade. The live UI uses ±1% thresholds and a news veto, while [app.py:515](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:515) tests any positive prediction without that veto. The replay also enforces no training cutoff and includes no execution timing, costs, or slippage. Use labeled rows before slicing, `expm1` for compounded returns, exclude unknown outcomes, and share the actual strategy rules. Require an untouched historical period or walk-forward predictions. Existing artifact metadata cannot establish whether any particular replay period was unseen; training overlap was not assumed.

8. **High — Historical cleanup depends on future observations.** [data_loader.py:52](C:/Users/Adi/Documents/GitHub/stock_pred/data_loader.py:52) interpolates and backfills OHLCV. Reproduction: `[100, missing, 300]` becomes `[100, 200, 300]`, while the same historical prefix `[100, missing]` becomes `[100, 100]`. Therefore a past feature/price can change when future observations arrive. Intraday backfill has a similar leading-gap risk. Validate candles and use explicitly causal handling; do not invent traded prices/volumes without exposing that choice.

9. **High — Custom symbols can escape model storage and exchanges collide.** [app.py:131](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:131) removes suffixes but does not validate paths. In-memory reproduction resolved `..\OUTSIDE` outside models/, and an absolute Windows path bypassed the model directory entirely. The resulting path is passed to `joblib.load`, which is an executable deserialization format. This becomes an execution risk if an attacker can cause a suitable artifact to exist at that path; that full exploit chain was not tested. `RELIANCE.NS` and `RELIANCE.BO` also map to the same artifact. Validate canonical symbols, preserve exchange identity, confine resolved paths to storage, and load only trusted artifacts. Apply the same identifier handling to trainer filenames.

10. **High — A stalled NSE request can block every tab.** [fii_dii.py:25](C:/Users/Adi/Documents/GitHub/stock_pred/fii_dii.py:25) and line 26 omit network timeouts. [app.py:567](C:/Users/Adi/Documents/GitHub/stock_pred/app.py:567) executes them synchronously on every rerun. Add bounded connect/read timeouts, HTTP/schema checks, limited retries, caching, and a visible unavailable state. Keep slow external feeds and training work from blocking unrelated app interactions.

11. **Medium — Opening-range boundaries and completion are wrong.** [intraday_logic.py:36](C:/Users/Adi/Documents/GitHub/stock_pred/intraday_logic.py:36) includes 09:30 in the 09:15–09:30 range. A fixture with an actual opening high of 101, a 09:30 high of 110, and later close of 104 reported Inside Range instead of a breakout. The function also returns a normal-looking result before the range is complete and substitutes the first available bar if opening bars are absent. Use an exclusive endpoint, completed-bar/session checks, and an explicit waiting/insufficient-data state.

12. **Medium — Live views accept stale data without freshness checks.** [live_price.py:22](C:/Users/Adi/Documents/GitHub/stock_pred/live_price.py:22) returns a price without its timestamp. Disconnected broker fallback is also fragile: [live_price.py:14](C:/Users/Adi/Documents/GitHub/stock_pred/live_price.py:14) dereferences `angel.session` without guarding `angel is None`, outside its exception handler.

13. **Medium — Intraday indices are insufficiently validated.** [data_loader.py:85](C:/Users/Adi/Documents/GitHub/stock_pred/data_loader.py:85) can convert invalid dates to `NaT` without removing them; duplicate timestamps remain. Further improvements across the project:

- **Model lifecycle:** Store training cutoff, creation time, feature/pipeline version, target definition, validation window/metrics, and dependency versions. Write artifacts atomically and avoid concurrent users overwriting a shared ticker file. The current daily packet has no training cutoff/version provenance; the saved intraday packet includes a 10m horizon absent from current source, and the saved Keras model has no inference path in the app. This is concrete source/artifact drift.
- **Error and cache handling:** [stock_list.py:34](C:/Users/Adi/Documents/GitHub/stock_pred/stock_list.py:34) substitutes a two-stock universe on failure, which the app caches for 24 hours. Preserve a last-known-good universe and retry degraded responses sooner. Button-only options/backtest results also disappear on later reruns; retain results with ticker/configuration identity in session state. Use structured, redacted logs rather than scattered prints and broad catch-and-continue behavior.
- **Incomplete algorithms:** The squeeze feature at [features.py:121](C:/Users/Adi/Documents/GitHub/stock_pred/features.py:121) checks only the upper channel boundary. Enhanced importance at [model_trainer.py:247](C:/Users/Adi/Documents/GitHub/stock_pred/model_trainer.py:247) is suppressed by a guard that does not match VotingRegressor's constituent estimators. The optimizer samples unsupported `max_features='auto'` for the installed sklearn version and does not catch failed trials. Finish or remove dormant experimental paths so advertised capabilities match executable code.
- **Architecture:** Split the 604-line app into presentation, data-provider adapters, feature construction, prediction/strategy, and backtesting modules. Keep feature construction deterministic and separate external fetching from feature computation. Define typed data/quote/artifact contracts and centralize symbols, market sessions, and configuration.
- **Testing and documentation:** No project test suite, CI workflow, README, lockfile, or root ignore policy was present. check_data.py prints a limited diagnostic and can claim complete health without checking imports, finite features, training sample size, or artifact compatibility. Add a clean-install/import smoke test; deterministic provider fixtures; prefix-invariance tests; training/inference schema checks; exchange-calendar/ORB/zero-volume tests; and independently calculated backtest examples. Document startup, secrets, supported assets, data freshness, model limitations, and artifact recreation. Exclude environments, caches, sensitive logs, and generated models from source distribution unless deliberately managed.
